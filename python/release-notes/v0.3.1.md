# Hibachi Python SDK v0.3.1 Release Notes

## Overview

Version 0.3.1 is a bug-fix and minor enhancement release. It corrects several issues with TPSL (take-profit/stop-loss) order handling and adds optional time-range filtering to the klines endpoint.

---

## What's New

### Optional Time Range for `get_klines`

`get_klines` now accepts optional `from_ms` and `to_ms` parameters to filter candlestick data by time range.

```python
# Fetch klines for a specific time window
klines = client.get_klines(
    "BTC/USDT-P",
    Interval.ONE_HOUR,
    from_ms=1700000000000,
    to_ms=1700003600000,
)
```

Both parameters are optional. Omitting them returns all available klines, preserving existing behaviour.

---

## Bug Fixes

### TPSL: `trigger_direction` now supported on `place_limit_order` and `place_market_order`

`trigger_direction` was previously only wired through for standalone trigger orders. It is now correctly forwarded for both limit and market orders.

```python
client.place_limit_order(
    "BTC/USDT-P", 0.001, 1_001_000, Side.ASK, max_fees_percent,
    trigger_price=1_000_000,
    trigger_direction=TriggerDirection.LOW,
)
```

### TPSL: parent order with TPSL legs can no longer also be a trigger order

The exchange rejects orders that are simultaneously a parent TPSL order and a trigger order. The SDK now raises `ValidationError` early rather than sending a request that will be rejected.

```python
# Now raises ValidationError immediately
client.place_market_order(
    "BTC/USDT-P", 0.001, Side.BUY, max_fees_percent,
    trigger_price=85_000,
    tpsl=TPSLConfig().add_take_profit(price=90_000),
)
```

### TPSL: leg trigger prices were being set incorrectly

TPSL child orders were receiving `max_fees_percent` as their trigger price instead of the leg's configured price. This is now fixed — each leg uses its own price as the trigger.

### TPSL: leg `trigger_direction` is now set automatically

TPSL child legs now have their `trigger_direction` set based on the parent order's side and whether the leg is a take-profit or stop-loss:

| Parent side | Leg type | `trigger_direction` |
|-------------|----------|---------------------|
| BID | Take-profit | HIGH |
| BID | Stop-loss | LOW |
| ASK | Take-profit | LOW |
| ASK | Stop-loss | HIGH |
