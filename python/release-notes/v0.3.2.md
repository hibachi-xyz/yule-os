# Hibachi Python SDK v0.3.2 Release Notes

## Overview

Version 0.3.2 is a bug-fix release. It corrects a deserialization failure in
`get_account_trades()` introduced when the exchange stopped returning
counterparty account ids in trade history.

---

## Bug Fixes

### `get_account_trades()` no longer raises `DeserializationError` on current API responses

On 2026-08-26 the exchange stopped returning `askAccountId`/`bidAccountId` on
`GET /trade/account/trades` as a security fix — a trader's own trade history
must not reveal who was on the other side of a fill. `AccountTrade` still
declared both as required constructor fields, so every call to
`get_account_trades()` failed with:

```
hibachi_xyz.errors.DeserializationError: Received invalid response ...
```

wrapping a `TypeError` raised while constructing `AccountTrade` from the
now-slimmer response.

`askAccountId` and `bidAccountId` are now `Optional[int]` and will always be
`None` — the exchange no longer sends them. `askOrderId`/`bidOrderId` are
also now `Optional[int]`: only the caller's own order id (on whichever side
matches `side`) is ever populated; the other is `None`.

```python
trade = client.get_account_trades().trades[0]
trade.askAccountId  # always None now
trade.bidAccountId  # always None now
```

No action is required from callers unless code explicitly read
`askAccountId`/`bidAccountId` (both always echoed the caller's own account id
even before this fix, so they carried no information the caller didn't
already have).
